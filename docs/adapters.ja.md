# ソースアダプター

Dependency Palaceは、ソースツリーを直接スキャンし、ビューアJSONを出力できるようになりました。

## クイックスタート

```bash
npm run scan -- /path/to/repo
npm run dev
```

デフォルトでは、スキャナーは`public/dependency-palace.graph.json`に書き込みます。アプリは起動時にそのファイルを取得し、自動的に開きます。
また、スキャナーは`public/dependency-palace.graph.json.diagnostics.json`に診断情報のサイドカーも書き込みます。ただし、`--diagnostics-out`が指定されている場合を除きます。
開発中はアプリが両方のファイルをポーリングするため、`--watch`を使うと手動のJSONアップロードなしでスキャン・オープン・リフレッシュループが動作します。

スキャナーはリクエストされたルート以下のすべてを読み込みます。リポジトリ全体やより狭いサブツリーを指定できます。

```bash
npm run scan -- ~/work/my-service/src/main --out my-service.graph.json --module-depth 2
```

ウォッチとコンパクト出力：

```bash
npm run scan -- ~/work/my-service --watch
npm run scan -- ~/work/my-service --format both
```

`--format both`はJSONと`public/dependency-palace.graph.dpg`（コンパクトな文字列テーブルグラフ）を出力します。JSONは引き続きポータブルなベースラインです。`.dpg`は大規模なローカルグラフ向けで、アプリのファイルボタンから読み込むことができます。

## 設定

[dependency-palace.config.example.json](../dependency-palace.config.example.json)を`dependency-palace.config.json`にコピーしてください。

```json
{
  "include": ["**/*"],
  "exclude": ["generated", "fixtures", "migrations"],
  "moduleDepth": 1,
  "maxFileBytes": 1500000,
  "cache": true,
  "cacheDir": ".dependency-palace/cache",
  "native": true,
  "watchIntervalMs": 1500
}
```

オプション:

- `include`: オプションのglob風パスパターン。空の場合はすべてのサポート対象ソースファイル。
- `exclude`: スキップするパス断片またはglob風パターン。
- `moduleDepth`: パスの何セグメントが3Dモジュール区画になるか。
- `maxFileBytes`: 巨大な生成ファイルの安全上限。
- `cache`: ファイルごとの抽出キャッシュを有効にする。
- `cacheDir`: キャッシュの場所。キャッシュキーにはアダプタのバージョン、相対パス、言語、モジュール深度、内容ハッシュが含まれる。
- `native`: ネイティブツール/プロジェクトのプロービングを有効にする。設定されたツールやプロジェクトマーカーが利用できない場合、スキャナーは理由を記録し、最初のパス抽出器を使用します。
- `watchIntervalMs`: `--watch`のポーリング間隔。
- `--diagnostics-out`: 明示的な診断JSONの出力先。
- `--clear-cache`: スキャン前にキャッシュを削除。
- `--no-cache`: キャッシュを読まず書かずに実行。
- `--no-native`: ネイティブプロービングをスキップし、最初のパスアダプターのみを使用。

## アダプター契約

すべての言語アダプターは同じ契約を実装します。

- 安定したアダプターIDとバージョン
- サポートされる拡張子とオプションのネイティブバックエンド宣言
- `nodes`、`links`、警告、出所を返す非同期抽出
- ネイティブツールがないまたは失敗した場合の決定論的なファーストパスフォールバック
- 出力がグラフにマージされる前の検証

スキャナーは、出力されるすべてのノードとリンクに出所情報を追加します。

```json
{
  "adapterId": "java-adapter",
  "adapterVersion": "native-adapter-v0.2.0",
  "language": "java",
  "backendId": "first-pass",
  "backendKind": "first-pass",
  "backendName": "ファーストパス構造解析器",
  "path": "src/main/java/com/acme/OrderService.java",
  "confidence": "medium",
  "source": "fallback"
}
```

キャッシュされた抽出も、2回目以降の変更されていないスキャンでは`"source": "cache"`の出所タグが付与されます。

## サポートされるアダプター

現在のスキャナーは依存性を抑え、リポジトリを即座に可視化することを目的としています。ネイティブバックエンドはローカルエコシステムツールやプロジェクトマーカーをプロービングし、利用可能性やバージョン診断を収集し、バックエンドが利用できない場合やメタデータのみの場合は決定論的なソース抽出器にフォールバックします。

| 言語 | 拡張子 | 今すぐ抽出される内容 |
| --- | --- | --- |
| Java | `.java` | パッケージ、インポート、クラス、インターフェース、列挙型、フィールド、メソッド、extends、implements |
| Haskell | `.hs`, `.lhs` | モジュール、インポート、データ/新タイプ/タイプ、レコードフィールド、型クラス、インスタンス、トップレベル関数、関数合成 |
| Kotlin | `.kt`, `.kts` | パッケージ、インポート、クラス、インターフェース、オブジェクト、列挙クラス、コンストラクター/タイプ関係 |
| Scala | `.scala` | パッケージ、インポート、クラス、トレイト、オブジェクト、列挙、extends |
| C# | `.cs` | 名前空間、using、クラス、インターフェース、列挙型、構造体、レコード、フィールド、メソッド、基本型 |
| TypeScript | `.ts`, `.tsx` | TypeScriptコンパイラーAPI構文解析、型のみ/ランタイムインポート、クラス、インターフェース、列挙型、型エイリアス、メンバー、extends、implements、シンプルな呼び出し/作成エッジ |
| JavaScript | `.js`, `.jsx`, `.mjs`, `.cjs` | TypeScript/JavaScriptパーサー、パース可能なインポート/require、クラス、メソッド、extends、シンプルな呼び出し/作成エッジ |
| Go | `.go` | `go.mod`対応のパッケージID、インポート、構造体、インターフェース、フィールド、埋め込みフィールド、レシーバーメソッド |
| Rust | `.rs` | `Cargo.toml`対応のクレートID、`use`、構造体、列挙型、トレイト、フィールド、トレイトメソッド、`impl`メソッド、トレイト実装エッジ |
| Python | `.py` | `python3`が利用可能な場合のPython `ast`、インポート、クラス、基本クラス、データクラス風フィールド、`self`フィールド、メソッド、動的呼び出しエッジ（ベストエフォート）；正規表現フォールバックと構文診断もあり |

| PHP | `.php` | 名前空間、use、クラス、インターフェース、トレイト、列挙型、フィールド、メソッド |
| Swift | `.swift` | インポート、クラス、構造体、プロトコル、列挙型 |
| C/C++ | `.c`, `.h`, `.cpp`, `.cc`, `.cxx`, `.hpp`, `.hh`, `.hxx` | インクルード、構造体/クラス/列挙型、シンプルなメンバー、コンパイルデータベース/CMakeマーカー診断 |

## ネイティブプローブモデル

アダプターはネイティブバックエンド候補を宣言できます。

- `native`: コンパイラー、AST、またはエコシステムネイティブパーサー
- `lsp`: 言語サーバーまたはインデックスベースのメタデータ
- `compiler-metadata`: 今後の意味解析器を導くためのプロジェクト/コンパイラー検出情報

ランナーは`Cargo.toml`、`go.mod`、`tsconfig.json`、`pom.xml`、`compile_commands.json`などのマーカーや、`cargo`、`go`、`tsc`、`javac`、`dotnet`、`clang`、`swift`、`ruby`、`php`などのツールをプロービングします。マーカーのプロービングは、多言語のサブディレクトリやスキャンルートも検索します。マーカーやツールが見つからない場合、スキャンは継続し、理由を診断に記録します（例：`プロジェクトマーカー未検出`、`必要なツールが利用できない`、`ネイティブメタデータ収集済み; グラフ抽出はフォールバックパーサーを使用`）。

共有ランナーは[src/extract/framework.ts](../src/extract/framework.ts)にあります。アダプター宣言とフォールバック抽出器は[src/extract/adapters.ts](../src/extract/adapters.ts)にあります。ネイティブアダプターの実装に関する課題は[issues](issues)で追跡されています。

## 診断と品質ゲート

すべてのスキャンは、以下を含む機械可読の診断情報を書き込みます。

- スキャンしたファイルとスキップしたファイル
- 言語ごとのファイル/ノード/リンク数
- 言語ごとのバックエンド数と警告数
- アダプターごとの集計数、バックエンド使用状況、検査ツールのバージョン/エラー
- ファイルごとのアダプター実行記録（キャッシュ/ネイティブ/フォールバック状態）
- 出力されたノードとリンクの合計
- 解決されていないエッジ数
- 出力パスとバイトサイズ
- キャッシュヒット、ミス、書き込み、アダプタ契約バージョン
- ネイティブプロービングの有効状態、ネイティブバックエンドの実行、フォールバック実行
- スキャン全体の所要時間
- アダプターの警告

CLIは各スキャン後に短い人間向け診断行も出力します。

次のコマンドで契約チェックを実行してください。

```bash
npm test
```

これは[fixtures/polyglot](../fixtures/polyglot)をスキャンし、出力されたグラフの形状を検証し、ノード/リンクの出所を確認し、キャッシュ再利用を検証し、アダプターの診断の一貫性を確認し、P0のHaskell/Javaの意味関係（レコード、型クラス、インスタンス、FP合成、Javaインターフェース、レコード、サービスフィールド、実装エッジ）を検証します。

## 望ましいネイティブアダプターの挙動

すべてのネイティブアダプターは、同じ正規化されたグラフを出力すべきです。

- 型ノード：クラス/インターフェース/列挙型/構造体/トレイト/プロトコル/モジュール
- メンバー：フィールド/プロパティとメソッド/コンストラクター/関数
- 関係：インポート、継承、実装、インスタンス、包含、構成、制約、派生、使用、呼び出し、作成、テスト
- `via`: 関係を引き起こしたメンバー
- `reason`: ソースやシンボルデータから抽出された短い説明
- 安定したID：言語が提供できる場合は完全修飾名
- 増分対応のメタデータ：ファイルパス、パッケージ/モジュール、シンボル範囲、内容ハッシュ

ビューアは、データがJava、Rust、Go、Pythonのどれから来たかを知る必要はありません。

## コンパクトグラフベンチマーク

次を実行：

```bash
npm run benchmark:graph-format -- public/examples/stress-dense-cycles.json 5
```

チェックイン済みのストレスグラフに対して、コンパクトファイルはJSONの約3分の1のサイズで、ローカルベンチマークでより高速にデコードされます。このベンチマークは意図的に狭く設定されており、グラフのパース/デコードコストを測定し、レンダリングやレイアウトは対象外です。
