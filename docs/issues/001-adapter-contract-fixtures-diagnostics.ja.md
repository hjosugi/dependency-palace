# アダプター契約、ゴールデンフィクスチャ、および診断

ラベル: `adapters`、`testing`、`developer-experience`、`priority:P0`、`status:ready`

## 問題点

ネイティブアダプターは、厳格な契約、フィクスチャ形式、および診断出力を共有しない限り、比較が不可能になる。

## 範囲

- 安定した `LanguageAdapter` インターフェースを定義する。
- アダプタの診断情報を追加：スキャンされたファイル、スキップされたファイル、出力されたシンボル、未解決のエッジ、警告。
- サポートされているすべての言語に対してゴールデンフィクスチャを追加。
- 正規化されたグラフ出力を比較するスナップショットテストを追加。
- アダプター出力のスキーマ検証を追加。

## 受け入れ基準

- すべてのアダプターはフィクスチャディレクトリに対して実行可能。
- スナップショット出力は決定論的。
- 診断情報は人間に読みやすい形式で出力され、機械可読なJSONに保存。
- 無効なアダプター出力はCIを失敗させる。
- フィクスチャのカバレッジにはクラス／インターフェース／フィールド／メソッド／継承／インポート／呼び出し例が含まれる。

## メモ

最初の実装は `src/extract` に存在する。この課題は、ネイティブアダプターが増える前にそれを堅牢にする必要がある。
