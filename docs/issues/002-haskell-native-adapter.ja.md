# ネイティブアダプター：Haskell

ラベル：`adapter`、`haskell`、`functional-programming`、`priority:P0`、`status:ready`

## 問題点

Haskellは後付けではなく、第一級のターゲットです。通常のオブジェクト指向の依存関係グラフでは、Haskellコードの重要な構造を捉えることができません：型クラス、インスタンス、代数的データ型、レコードフィールド、制約、トップレベル関数、関数合成パイプライン。

## 目的

コードのメンタルモデルを可視化するネイティブなHaskellアダプターを構築します：

- `data`、`newtype`、レコードフィールドをデータ本体と合成エッジとして表現。
- `class` 宣言を契約／型クラスの表面として表現。
- `instance` 宣言を実装エッジとして表現。
- 型クラス制約を契約依存関係として表現。
- トップレベル関数を振る舞いノードとして表現。
- `(.)`、`(>=>)`、`(<=<)`、`>>=`、`=<<`、`<$>`、`<*>`を合成エッジとして表現。
- `deriving`句を生成された振る舞いエッジとして表現。

## 候補バックエンド

- GHC API。
- Haskell Language Server / HIEファイル。
- `hiedb`によるシンボルとリファレンスの検索。
- CabalおよびStackによるプロジェクトの検出。
- フォールバックのパーサーとしてTree-sitter Haskell。

## 必須抽出項目

- モジュールとインポート（修飾インポートやエイリアスを含む）。
- データ／newtype／タイプ宣言。
- レコードフィールドとフィールドタイプ。
- 型クラスとメソッドのシグネチャ。
- インスタンスとターゲットタイプ。
- deriving戦略と派生クラス。
- トップレベル関数とそのシグネチャ。
- シグネチャ内の型クラス制約。
- 関数合成とモナド／アプリカティブパイプライン。
- シンボルのソース範囲。

## 受け入れ基準

- 素の`.hs`ソースツリーで動作。
- CabalおよびStackプロジェクトで動作。
- `Module.Type`、`Module.function`、`Module.Typeclass`などの安定したIDを出力。
- レコードフィールドの合成を`contains`でキャプチャ。
- 型クラスインスタンスを`instance`でキャプチャ。
- FPパイプラインを`composes`でキャプチャ。
- トップレベル関数と型クラスメソッドを区別。
- ゴールデンフィクスチャにはレコード、型クラス、インスタンス、deriving、`>=>`合成を含む。

## 現在の第一段階の状況

軽量スキャナーはすでに`.hs`／`.lhs`、モジュール、インポート、`data`／`newtype`／`type`、型クラス、レコードフィールド、トップレベル関数、deriving、制約、一般的な合成演算子を認識しています。この課題はコンパイラーグレードの正確さを追求したものです。
