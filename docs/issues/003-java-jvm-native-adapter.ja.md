# ネイティブアダプター：Java/JVM

ラベル：`adapter`、`java`、`jvm`、`priority:P0`、`status:ready`

## 問題点

Javaはクラス中心のエンタープライズコードベースの主要なターゲットです。正規表現による抽出だけでは、オーバーロード、ジェネリクス、アノテーション、ネストされたクラス、メソッド呼び出し、クロスモジュールのシンボルには対応できません。

## 候補バックエンド

- `javac`コンパイラAPI。
- Eclipse JDT。
- 軽量パース用のJavaParser。
- 依存関係のエッジのためのバイトコードフォールバック。
- Gradle/Mavenのプロジェクト検出。

## 必須抽出項目

- パッケージ、インポート、静的インポート。
- クラス、インターフェース、レコード、列挙型、アノテーション。
- 可視性、静的、抽象、アノテーション付きのフィールドとメソッド。
- 継承と実装。
- フィールドの構成 / 所有権を`contains`として表現。
- コンストラクタ注入された依存関係を構成エッジとして。
- コンストラクタ呼び出しとメソッド呼び出し。
- フィールドの型参照とパラメータ/戻り値の型参照。
- テスト専用の依存関係。
- シンボルのソース範囲。

## CLI UX

```bash
npm run scan -- ./my-java-repo --out graph.json
npm run scan -- ./service/src/main/java --out graph.json --module-depth 2
```

## 受け入れ基準

- プレーンなソースフォルダで動作すること。
- MavenとGradleのルートを検出できること。
- 完全修飾クラス名を出力。
- メソッド呼び出しエッジを`via`でリンク。
- 内部クラスやレコードを処理。
- Springスタイルのサービス/リポジトリ/コントローラーコードを含むフィクスチャカバレッジ。
