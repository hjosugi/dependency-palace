# WebGPU レンダーパイプラインとワーカーのレイアウト

ラベル: `レンダリング`, `webgpu`, `パフォーマンス`, `アーキテクチャ`, `優先度:P0`, `状態:準備完了`

## 問題点

現在のビューアはThree.jsのシーンオブジェクトを通じてレンダリングしています。これは最初の製品スライスには十分ですが、非常に大きなグラフにはより明示的なレンダリングパイプラインが必要です。

## 目標

Dependency Palaceを最新のWebGPU優先アーキテクチャに向けて移行します：

- デフォルトでWebGPUレンダーを使用。
- WebGLのフォールバックをサポート。
- ワーカーによるレイアウトと解析。
- 型付き配列のレンダーバッファ。
- LOD（詳細レベル）とエッジのカリング。
- 将来的な計算支援によるレイアウト。

## 範囲

- Reactやグラフの意味論に依存しないレンダーバッファモデルを作成。
- レイアウト／解析作業をWebワーカーに移行。
- ワーカーからメインスレッドへ型付き配列を転送。
- ノード／エッジバッファを段階的にアップロード。
- UIにバックエンドの診断情報を追加。
- WebGLのフォールバックパスを維持。

## 受け入れ基準

- アプリが`webgpu`または`webgl`のバックエンドを報告。
- グラフの変更が大きなフィクスチャデータでUIのブロックを引き起こさない。
- ワーカーの出力が決定論的。
- レンダーバッファのサイズ（バイト単位）とアップロード時間を測定。
- 1万タイプ／10万エッジの合成グラフをフィルタリング・フォーカスしてもUIがフリーズしない。
- WebGLのフォールバックが視覚的に同等。

## 備考

セマンティックなレイアウトを純粋な力指向のシミュレーションに置き換えないこと。WebGPUの計算は安定したメンタルモデルを洗練させるものであり、別の動く髪の毛の塊を作り出すものではない。
