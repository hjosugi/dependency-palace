# スタートアップと例のペイロードパフォーマンス

ラベル: `performance`, `viewer`, `examples`, `priority:P0`, `status:ready`

## 問題点

ビューアは数千のシンボルを探索できるにもかかわらず、軽快に感じられる必要があります。大きな例や生成されたグラフが最初の画面の動作を鈍くしないようにすべきです。

最近の作業では、重いスタートアップデモを小さなスターターグラフに置き換え、大きな例のメンバーペイロードも削減しましたが、まだ改善の余地があります。

## 目標

普通のノートパソコンでも、スタートアップと例の切り替えを一貫して高速に行えるようにする。

## 範囲

- スターターグラフを小さく保つ。
- 重い例は明示的なクリック時のみ読み込む。
- 各例のペイロードサイズを報告に追加。
- 本番ホスティング用にgzip/Brotliサイズのメモを追加。
- 可能な限りメインスレッドで大きなJSONの解析を避ける。
- 大きな例の取得と正規化のためのローディング状態を追加。
- グラフペイロードをサマリーと詳細チャンクに分割することを検討。

## 受け入れ基準

- 初期アプリ起動時に数千ノードのグラフを生成しない。
- 例のインデックスは未圧縮で20 KB以下に保つ。
- ストレス例はUIをロックせずに読み込め、目立つ一時停止が1回以上発生しない。
- パフォーマンスに関するメモは`docs/examples.md`に記録されている。
- 視覚的な検証は小さな例とストレス例の両方を正常にロードできる。

## 備考

長期的な解決策は、ワーカー所有のグラフ解析やバイナリグラフフォーマットの問題と重なる可能性が高い。
