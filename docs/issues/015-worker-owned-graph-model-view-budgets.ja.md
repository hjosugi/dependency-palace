# ワーカー所有のグラフモデルとビュー予算

ラベル: `パフォーマンス`, `ワーカー`, `グラフモデル`, `優先度:P0`, `状態:準備完了`

## 問題点

正規化、SCC分析、フィルタリング、フォーカス拡張、ビュー予算の処理は現在メインスレッド上で実行されています。これは小規模な例では問題ありませんが、実リポジトリではリスクがあります。

## 目標

グラフモデルの処理をWebワーカーに移し、ビュー予算を明示的に、計測可能に、テスト可能にする。

## 範囲

- `normalizeGraph`、`analyzeGraph`、`buildViewGraph`、レイアウト準備をワーカー境界に移動。
- 転送可能な型付き配列やコンパクトなJSONメッセージを使用してレンダリング準備済みの出力を行う。
- 出力の決定性を保持。
- ワーカーのタイミング（パース、正規化、SCC、フィルタ、レイアウト、転送）を報告。
- 移行中は現在のメインスレッド経路をフォールバックとして維持。

## 受け入れ基準

- 2,000以上のノードを持つストレスグラフの読み込み時にUIコントロールが応答し続けること。
- ワーカーが現在のメインスレッドモデルと同じノード/リンク数を返すこと（フィクスチャに対して）。
- ビュー予算は設定可能な定数またはオプションであり、隠された魔法ではないこと。
- フォーカスビューは常に選択されたノードと直接的な意味的関係を保持すること（可能な限り）。
- Playwrightによる検証がワーカー有効時に合格すること。
