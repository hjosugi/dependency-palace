# Haskell/Java 品質ゲート

ラベル: `haskell`, `java`, `アダプター`, `テスト`, `優先度:P0`, `状態:準備完了`

## 問題点

Haskell と Java は最も重要なプログラミング言語です。これらには、単なる最善努力の抽出を超えた品質ゲートが必要であり、リグレッションを早期に検出する必要があります。

## 目的

Haskell と Java の意味論に対するフィクスチャ駆動の受け入れテストを作成する。

## 範囲

- Haskell のフィクスチャカバレッジ:
  - モジュール/インポート
  - `data`、`newtype`、レコード
  - 型クラスとスーパークラスの制約
  - インスタンス
  - 派生
  - トップレベル関数
  - 関数合成
- Java のフィクスチャカバレッジ:
  - パッケージ/インポート
  - クラス/インターフェース/列挙型
  - extends/implements
  - フィールドとフィールドの合成
  - メソッド/コンストラクター
  - 最善努力の呼び出し/作成関係
- 期待される `RawGraph` 出力のスナップショット。
- キー関係の欠落に対して失敗するスキャナーテストを追加。

## 受け入れ基準

- `npm test` または同等のスクリプトが Haskell と Java のフィクスチャを検証する。
- 各 P0 関係タイプに少なくとも一つの肯定的なフィクスチャアサーションが存在する。
- フィクスチャの失敗は、見やすい欠落ノード/欠落エッジの診断を出力する。
- ドキュメントは、テスト失敗とは別に既知の最初のパスの制限を明示する。
