# 可視化の比喩

Dependency Palaceは複数の3D比喩をサポートしています。なぜなら、コードの理解は一つの形だけではないからです。

同じグラフは異なる形に投影できます：

| 形態 | 最適な用途 | マッピング |
| --- | --- | --- |
| パレス | デフォルトの意味論的アーキテクチャビュー | 選択されたタイプを本体、状態を左、振る舞いを右、契約を上、構造を下に配置 |
| ツリー | 継承、所有権、ルート、枝 | 選択されたタイプを幹、フィールドを根、メソッドを枝、契約を樹冠に配置 |
| ブロック | システム構築とモジュール作成 | 選択されたタイプを中央のブロック、依存関係を周囲のブロックとしてビルドグリッドに配置 |
| ライフ | 実行時の有機体 / 生きているシステム | 選択されたタイプを核、フィールドを内部状態、メソッドを受容体、依存関係を容器として配置 |
| スペース | 大規模な方位と軌道 | 選択されたタイプを星、フィールド/メソッドを惑星、契約と依存関係を軌道リングに配置 |
| アトミック | 微細な局所構造 | 選択されたタイプを核、メンバーを電子殻、関係を結合として配置 |
| シティ | システム規模の方位：地区、ブロック、スカイライン | 選択されたタイプをダウンタウンの市庁舎、メンバーを広場、関係グループを建物の地区、遠隔の文脈を郊外として配置；建物の高さと面積はメトリクスをエンコード |

## ルール

比喩は意味論的グラフを隠してはなりません。むしろ、異なるメンタルモデルを明らかにすべきです：

- ツリーは系譜と構成を強調します。
- ブロックは構築と包含を強調します。
- ライフは状態/振る舞いの流れを強調します。
- スペースはスケールと軌道を強調します。
- アトミックは局所的な内部構造と小さな粒度の関係を強調します。
- シティはシステム規模、近隣、そして共有された地面に立つメトリクス駆動のスカイラインを強調します。

## 実装

標準的な意味論的レイアウトは依然として真実の源です。比喩は[layout.ts](../src/graph/layout.ts)内のfocus-layoutノードに対する変換パスです。

これにより、インタラクション、選択、検索、関係フィルタリングは安定したまま、視覚的な形態だけを変えることができます。

## 将来の形態

これらは意図的に将来の投影として保持されており、別のデータモデルではありません：

- サーキット：インターフェースをソケット、呼び出しを信号トレース、アダプターを基板として表現。
- リバー：データフローと構成パイプラインをストリームとして表現。
- 星座：建築のランドマークとハブを名前付きの星として表現。
- アーカイブ：モジュールを棚、安定した公開APIを背骨、揮発性の内部を緩いドキュメントとして表現。
