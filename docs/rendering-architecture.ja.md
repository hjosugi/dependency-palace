# レンダリングアーキテクチャ

Dependency PalaceはWebGPUを優先し、WebGLをフォールバックとするレンダリングアーキテクチャを採用しています。

## 現在のランタイム

```text
RawGraph JSON
  -> グラフワーカー
  -> normalizeGraph / analyzeGraph / buildViewGraph / layoutViewGraph
  -> GraphScene
  -> WebGPURenderer（利用可能な場合）
  -> WebGLRenderer（それ以外の場合のフォールバック）
```

レンダラーは [GraphScene.tsx](../src/GraphScene.tsx) で初期化されます。

- `three/webgpu` を動的に試行します。
- `navigator.gpu` が存在し、初期化に成功した場合は `WebGPURenderer` を使用します。
- WebGPUが利用できない場合は `WebGLRenderer` にフォールバックします。
- 両バックエンドで同じシーングラフとインタラクションモデルを維持します。
- アクティブなバックエンド、推定バッファバイト数、アップロード時間をステージメトリックストリップに報告します。

動的インポートによりアプリシェルが小さくなり、WebGPUバックエンドを使用できないブラウザでの読み込みを回避します。

## なぜWebGPU優先か

WebGPUはこのプロジェクトにとって適切な方向性です。対象のワークロードは通常の3Dシーンではなく、大規模で動的なデータビジュアライゼーションだからです。

- 多数のノードとリンク
- 頻繁なフィルタリングとフォーカス変更
- 大きな型付きバッファ
- レイアウト計算の可能性
- 将来的なエッジバンドルや可視性カリング

短期的な実装ではThree.jsのシーングループオブジェクトを使用しますが、アーキテクチャは明示的なGPUバッファとワーカー所有のレイアウトに向かって進むべきです。

## レンダリングレイヤー

| レイヤー | 責任範囲 |
| --- | --- |
| アダプタレイヤー | ソースコードからシンボルと関係を抽出 |
| グラフモデルレイヤー | 正規化、集約、SCC分析、フォーカスビュー構築 |
| レイアウトレイヤー | 安定した位置と意味的配置の生成 |
| レンダーデータレイヤー | 位置付けられたグラフを型付き配列に変換 |
| レンダラー層 | バッファをアップロードし、ノード/エッジを描画 |
| インタラクション層 | ピッキング、ホバー、選択、カメラ、検索 |

## パフォーマンスルール

- グラフノードごとにDOMノードを持たない
- グラフノードごとにReactコンポーネントを持たない
- レンダーループ内で常時動作するフォースシミュレーションを行わない
- 繰り返しのビジュアルフォームにはインスタンス化を使用
- エッジは共有バッファジオメトリにバッチ処理
- ラベルはUIオーバーレイに保持し、数千のワールド空間テキストメッシュは避ける
- GPUアップロード前に意味的フィルタリングを優先
- レイアウト前にビュー予算を適用：フォーカスビューは選択/直接/意味関係を優先、クラスビューはGPUアップロード前に極端なリンク数を制限
- 重いレイアウトと分析はWeb Workersに移行
- 非常に大きなグラフをサポートする前にLODとエッジ可視性ルールを追加

## バックエンド計画

### フェーズ1：WebGPU優先のThree.js

完了済み：

- `WebGPURenderer` の動的インポート
- WebGLフォールバック
- キャンバス上のバックエンドマーカーによる検証
- 既存のインスタンス化されたノードメッシュとバッチ化されたエッジライン
- レイアウト/レンダリングアップロード前のグラフモデル層でのフォーカス/クラスビュー予算
- 静かな、バランスの取れた、フルビュー用のエッジ密度プリセット
- Mapビューでのパッケージレベルのエッジバンドル
- 選択ノードの直接エッジをリンク予算で優先
- `npm run verify:large-view` で10kノード/100kエッジの合成グラフを概要とフォーカス予算に対して検証

### フェーズ2：ワーカーレイアウト

現在のJSON/コンパクトグラフ境界に対して完了：

- SCC検出
- クエリフィルタリング
- フォーカス近傍の拡張
- パッケージの集約
- セマンティックレイアウト

次のステップ：非常に大きな出力にはトランスファラブル型付き配列を使用

### フェーズ3：レンダーバッファモデル

明示的なレンダーバッファを導入：

- `Float32Array`によるノード位置
- `Float32Array`によるノード寸法
- `Uint32Array`によるノードカラーまたはパックカラー
- `Float32Array`によるエッジセグメント位置
- `Uint8Array`によるエッジタイプとフラグ

これにより、グラフの意味論とGPUアップロードの間に安定した境界が生まれます。

### フェーズ4：LODとカリング

追加：

- カメラ距離に基づくノードLOD
- エッジ密度の上限設定
- パッケージペア間のエッジバンドル
- フラスタムカリングによる遠距離クラスターの除外
- 非常に大きなグラフ向けのフォーカス優先インタラクション

### フェーズ5：計算支援レイアウト

WebGPUサポートがこのアプリのターゲットユーザに十分成熟したら：

- オプションのフォースリラクゼーションを計算シェーダで実行
- セマンティックレイアウトを安定した基盤として維持
- ローカルな微調整、エッジバンドル、衝突軽減のために計算を使用
