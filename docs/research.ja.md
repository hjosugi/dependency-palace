# 研究ノート

目的は、3Dで2D UMLキャンバスを再現することではありません。役立つターゲットは、開発者がコードを完全に理解した後に構築するメンタルモデルです：状態、振る舞い、契約、継承、呼び出し元、呼び出し先、アーキテクチャの区分。

製品のメンタルモデルは [mental-model.md](mental-model.md) に保持されています。
明示的な研究ターゲットリストは [research-targets.md](research-targets.md) に保持されています。

## 製品の決定事項

1. 詳細前に概要。大規模コードベースはパッケージの概要から始め、複雑な絡まりを避ける。
2. 安定したレイアウトをライブ物理シミュレーションの上に。レイアウトは決定論的で、モジュール/パッケージでクラスタリング。フォースレイアウトは発見に有用だが、ランドマークを動かす可能性も。
3. フォーカスは主要モード。ノード選択と1-3ホップの展開は Sourcetrail/NDepend パターンに従う：ローカルな依存関係を調査しつつ、グローバルマップを失わない。
4. メトリクスが可視性を駆動。次数、SCCサイズ、LOC、複雑さ、パッケージサイズでサイズ付けと優先順位付けを行う。
5. レンダリングは意図的に低レベル。ノードは1つの `InstancedMesh`、リンクは1つの `LineSegments`、ラベルはホバー/選択のためだけにDOM内に保持。
6. 有用なフォーカスビューはクラス内部も表示。フィールドとメソッドは所有オブジェクトとしてレンダリングし、隠されたメタデータではない。
7. 複数の3D形態は意味を保持する限り有用：アーキテクチャのための Palace、階層のための Tree、構築のための Blocks、状態/振る舞いのための Life、スケールのための Space、局所内部のための Atomic。

## パフォーマンス戦略

現行レンダラーの予算：

- 表示されているノードごとに1つの描画コール。
- 表示されている依存エッジごとに1つの描画コール。
- ノードごとのReactコンポーネントはなし。
- 連続したレイアウトシミュレーションはなし。
- ポインタピッキングは `requestAnimationFrame` で制御。
- パッケージの集約は数千クラスのグラフのデフォルト。

さらに大規模なグラフ向け次のステップ：

- レイアウトとSCC分析をWeb Workerに移行。
- パッケージペアごとのエッジバンドルを追加。
- カメラ距離が増すにつれて低次数エッジをフェードまたは非表示にするレベル・オブ・ディテールルールを追加。
- 非常に大きな抽出グラフ用のバイナリキャッシュフォーマットを追加。
- ソーステキストの解析ではなく、言語ごとのソース抽出器を追加。
- レイアウト、フィルタリング、GPUアップロード、レンダーフレーム周りに明示的なパフォーマンストレースを追加し、HPCプロファイリングワークフローに触発。
